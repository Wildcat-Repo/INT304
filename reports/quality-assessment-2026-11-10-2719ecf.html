Executive Summary

employee-form is a small, well-tested React 19 app built for the INT304 course. It collects employee details and saves both a draft and a submitted list to localStorage. The code is readable, persistence handles corrupt data safely, and the 12-test suite covers both components at 100% line coverage. The main gaps are operational, not structural. There is no CI, the form accepts empty or duplicate submissions, employee data is logged to the console, and the Create React App toolchain brings in 36 npm advisories (15 high). The advisories affect build/dev tooling only. This is the first assessment, so there is no previous report to compare against.

Project Overview

A Create React App project with an App component that holds the employees array and a class-based EmployeeForm with Name, Email, Title, and Department fields. Form input is saved as a draft under the localStorage key current_employee; each submit appends the employee to the employees key. Hosted on a self-hosted Gitea instance (UAGC/employee-form) and mirrored to GitHub.

Medium (4)

MEDIUM Form accepts empty or invalid submissions
id no-form-validation · dimension production_readiness · src/Components/EmployeeForm.js:46-51 · src/Components/EmployeeForm.js:58-94
handleSubmit forwards this.state unchecked; inputs have no required attribute, so an empty record is saved to employees.
Recommendation: Add required to the inputs (the browser then checks type=email too) and/or check for blank values in handleSubmit before calling onSubmit.
MEDIUM Draft stays after submit, so repeat clicks save duplicates
id draft-not-cleared-on-submit · dimension production_readiness · src/Components/EmployeeForm.js:46-51
After onSubmit the state and current_employee are left unchanged; each further Submit click appends the same employee again.
Recommendation: Reset state to the defaults after a successful submit (componentDidUpdate will then clear the saved draft).
MEDIUM 36 npm advisories (15 high) through react-scripts
id transitive-npm-advisories · dimension security · package.json:12 · package-lock.json
npm audit: nth-check, postcss, webpack-dev-server, serialize-javascript, svgo and others, all pulled in by react-scripts 5.0.1. They affect build/dev tooling, not the shipped bundle.
Recommendation: Accept the risk for coursework, or move to Vite (@vitejs/plugin-react) to remove the deprecated CRA dependency tree. Do not run npm audit fix --force, which downgrades react-scripts.
MEDIUM Employee data written to the console
id pii-console-logging · dimension security · src/App.js:19 · src/App.js:30
console.log('Saving data:', data) and console.log('Adding employee:', employee) print names and emails in production builds.
Recommendation: Remove the logs or wrap them in a process.env.NODE_ENV === 'development' check.

Reads are protected, but writes can throw QuotaExceededError (e.g. Safari private mode, full storage) and crash the render cycle.

Conclusion

For a course assignment, the app is in good shape: it is correct for the expected path, defensively coded where it reads storage, and unusually well tested. The quickest improvements are housekeeping (commit the README, remove debug logging and dead code) plus two behavior fixes (validation and clearing the form after submit). Adding CI would protect the test suite you already have. DevOps (3.5) and Production Readiness (5.0) are below 6.5; run quality-dimension-check on those for more detail.
